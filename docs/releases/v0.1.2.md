# BPL v0.1.2

A patch release covering the staging baseline from v0.1.1 through PR #217.

## Highlights

- Standalone `bpl` executable with an embedded standard library, prebuilt
  binaries for Linux and macOS (x64 and arm64), and a one-line installer.
- `bpl test` runs `test` frames in `*_test.bpl` files (`--list`, `--fail-fast`),
  with assertion helpers that report expected and actual values. `bpl new`
  projects include tests.
- New CLI conveniences: `bpl -e` and `bpl --stdin`, `bpl check` and `bpl dev`
  without arguments use the project entry, and `bpl format --diff`.
- Linter rules L002 to L009 (unused imports and private functions, constant
  and repeated conditions, self-assignment and self-comparison, empty branches,
  values overwritten before they are read), `bpl lint --fix`, `--disable` and
  project settings in `.bpllint.json`.
- Language: nested patterns in struct variant fields and module-qualified enum
  variants in values, patterns and `switch`; a warning for implicit
  integer-to-`bool` conversion; reserved words used as names are reported at
  the name.
- Standard library: regular expressions, arbitrary-precision integers,
  SHA-1/256/384/512, HMAC, HOTP/TOTP, CRC-32, Adler-32, FNV-1a, Base32,
  URL-safe Base64, URL percent-encoding, v7 UUIDs, secure entropy, leveled
  logging, ISO 8601 parsing, JSON pretty-printing, checked number parsing,
  dotenv loading, shell-free process execution, and additions to `Array`,
  `Map`, `Set`, `FS`, `Path`, `Rand`, `StringBuilder`, `Option` and `Result`.
- Editor (LSP): references for struct members, import aliases and namespaces,
  signature help and completion fixes.
- A rewritten playground and tutorial frontend with Markdown lesson text.
- A compiler fuzzer with an exact output oracle, several audit rounds of
  compiler, standard-library and package fixes, and faster module resolution
  and code generation.

The full list is in the [changelog](../../CHANGELOG.md).

## Compatibility notes

Stricter checks can reject programs that were accepted before, for example
reserved words used as names and data-carrying enum variants used without their
payload. The repository is now formatted with Prettier and `bpl format`, and CI
checks both. This remains an early 0.1.x development release with manual
ownership and native-interoperability responsibilities.

## Validation

The release head passes the repository CI on its pull request to `master`,
including the release-binaries smoke builds. Version tags follow the
repository's tested container-image publication workflow; image availability
follows that workflow's successful completion. No npm publication is performed.
