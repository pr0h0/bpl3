# BPL v0.1.2 — prepared release candidate

This release is prepared but not published. No v0.1.2 tag or registry publication
is created by the preparation PR. The maintainer controls the release decision.

## Changes since 0.1.1

PR #85 fixes three generic-inheritance and dispatch defects:

- Inherited override signatures now use instantiated generic-parent arguments,
  including transitive parents, while preserving method generic shadowing and
  the distinction between value and pointer receivers.
- Generic receiver bindings are prepared before inherited lookup and direct
  virtual dispatch. Parent-pointer calls passed through free functions select
  the derived override instead of falling back to the parent implementation.
- Bound parent methods retain derived virtual dispatch through their selected
  vtable entry. Receiver expressions evaluate once, and value-receiver adapters
  copy the correct derived layout on invocation.

Bound methods still borrow receiver storage; they do not extend its lifetime.
Lifecycle methods retain direct binding, null binding is diagnosed, and variadic
value-receiver bindings remain unsupported. This is a correctness release, not
an ownership or generic-language redesign.

## Validation and release preparation

The implementation head e7577d3e passed all configured PR #85 checks and its full
CodeRabbit assessment had no actionable findings or retained architecture
concerns. The staging merge f71856a6 has the identical tested source tree.
Native O0/O3 and hosted Wasm cases cover concrete/generic and transitive parents,
aliases, callback arguments, value receivers, receiver evaluation and null paths.

Release preparation also includes the 0.1.1 metadata and packaging corrections,
so schema allowlists, packed completions and JSON no-input diagnostics are not
regressed. The combined candidate must pass release checks and final PR CI before
it is promoted or published. Audit reports and private evidence remain excluded
from archives. Downloaded npm tarballs are artifacts, not npm registry publication.
