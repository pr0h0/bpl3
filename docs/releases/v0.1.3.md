# BPL v0.1.3

A patch release covering the staging baseline from v0.1.2 through PR #252.

## Highlights

- Language: a `*Spec` value holds its object pointer and method table by value,
  so spec values can be returned, stored in fields and compared; `is`/`as`
  check a spec value's exact type. `\xHH` in a string literal is one raw byte.
  Literal match patterns must have the matched value's type, and may be
  negative. Growing generic instantiation cycles are reported as
  `BPL_TYPE_RECURSION_CYCLE`.
- Exceptions: an `@[auto_destroy]` local is destroyed when a function it calls
  throws. `try`/`catch`, `throw` and `defer` work on WebAssembly.
- Performance: a method call on a struct that nothing inherits from is a direct
  call, about five times faster in method-heavy code. Large native builds
  compile in a worker that exits before clang runs, and split IR of 4 MB or
  more into parallel clang jobs: on a 48k-line program peak memory falls from
  about 1.1 GB to 650 MB and build time from 77 s to 30 s.
- Standard library: threads and synchronization, iterators, more data
  structures, compression and many additions to existing modules.
- Packages: `bpl-json`, `bpl-json-schema`, `bpl-jwt`, `bpl-cache`,
  `bpl-metrics`, `bpl-markdown`, `bpl-log` and `bpl-websocket`, plus cookies,
  keep-alive and wildcard routes in `bpl-express`, multipart parsing in
  `bpl-web-middleware` and new `bpl-validation` checks.
- `apps/bpl-quant`, a 48k-line quantitative-finance service, exercises the
  compiler, standard library and packages as a large application.
- Fixes from a language conformance audit, generic code generation, the
  fuzzer and the language server; hosted WebAssembly `printf` handles `%i`,
  `%u` and 64-bit integers.

The full list is in the [changelog](../../CHANGELOG.md).

## Compatibility notes

Breaking changes: `*Spec` values change layout, `\xHH` escapes are raw bytes,
literal patterns are type-checked, and several misuses that produced invalid
IR are now compile errors. The VS Code extension needs VS Code 1.91 or newer.
Known open issues are listed in `docs/project/BUGS.md` (BUG-551, BUG-602,
BUG-703, BUG-803). This remains an early 0.1.x development release.

## Validation

The release head passes the repository CI on its pull request to `master`,
including the release-binaries smoke builds. Version tags follow the
repository's tested container-image publication workflow; image availability
follows that workflow's successful completion. No npm publication is performed.
